# 言葉で組み立てる景色

「ひかりの箱」の操作対象を、色と動きの設定から、物体を組み合わせるシーン構成へ拡張しました。
料理や庭などを名前に対応した固定プリセットへ振り分ける方式ではありません。
AIが共通の形・配置・動作を組み合わせ、端末内の描画機能がその記述を実行します。

## 操作できること

| 対象 | 操作 |
| --- | --- |
| 光の数と見た目 | 0〜1,024個、サイズ、基本色・アクセント色、単色・混色・虹・高さ・速さによる配色、発光、軌跡 |
| 光の動き | 漂う、群泳、公転、雨、雪、炎、噴水、繰り返す花火、形への整列 |
| 群れ | 近傍の粒との位置・速度を参照する結合・整列・分離、1〜6群、移動する誘導点 |
| 粒の形への整列 | 球、輪、ハート、星、らせん、銀河、格子、波、トーラス、立方体、魚、鳥、蝶、花、任意の点列、体積配置。形を維持した群泳と形同士の連続変形 |
| 力と操作への反応 | 風、重力、乱れ、粘り、渦、傾きの感度、振ったときに集める・散らす・反応しない |
| 物体 | 球、箱、円柱、円錐、トーラス、円盤、星、ハート、葉、魚、花、独自輪郭の多角形、鳥、木、岩、中が空いた器、曲線チューブ／リボン、水面、ゾウ・キリン・ライオン |
| 物体の編集 | 識別名ごとに位置・幅・奥行き・高さ・3軸回転・色・発光・輪郭のゆらぎを変更、追加・削除 |
| 繰り返し配置 | 直線、輪、格子、らせん、散らす。1組につき32個、全体で256個まで |
| 物体の動作 | 回転、上下動、公転、伸縮、波、揺れ、滑らかな経路、飛行・遊泳、羽ばたき、曲線に沿う吸い上げ／流れ、変形、波紋。最大6種類の動作を重ね合わせ |
| 物体同士の連動 | 親子階層（最大8段）、回転軸、関節の回転、同じ親と一緒に動く部品 |
| 物体と箱の連動 | 傾けると移動・傾く、振ると弾む。その両方、または反応なし |
| 世界とカメラ | 背景・床の色、世界全体の見た目の明るさ、ブルーム、箱の枠の表示、視点の角度・ズーム、動作範囲に基づく自動構図、主照明・補助照明・最大4灯の局所照明、粗さ・金属感・影 |
| 編集履歴 | 16段階の戻す／やり直す、景色全体の保存・呼び出し |

物体の組は最大48組です。ひとつの組に形と繰り返し配置を指定できます。
多角形は3〜32頂点の、穴や自己交差のない輪郭を立体化します。
任意の画像や既存モデルをダウンロードすることなく、端末内で形を生成します。

世界の単位はcm、上方向はZ、床はZ=0です。目安の範囲はX±300、Y±200、Z=0〜350です。
物体の位置は中心、大きさは回転前の全幅・全奥行き・全高です。
粒はX±275、Y±180、Z=45〜335の中で動きます。

## 頼み方の例

- 「光を今の3倍に増やして、赤と金にして」
- 「イワシの群れみたいに泳がせて。群れを二つに分けて」
- 「小さな森と家を作って、星を浮かべて」
- 「桜の木の隣にベンチを置いて、花びらを風に流して」
- 「目玉焼きを作って」「黄身を二つにして、皿の周りに星を並べて」
- 「ロケットを組み立てて、上へ打ち上げて」
- 「太陽を真ん中に置いて、周りを惑星が回るようにして」
- 「その星をもっと大きく」「背景を夕焼けに」「箱を振ったら家が弾むように」
- 「粒をハートの形に並べて」「虹色の波にして」
- 「元に戻して」（1段階戻す操作は端末内でも受け付けます）

AIの構成と解釈によって結果は変わります。固有の細かな造形、写実的なモデル、音、
新しいゲームルール、任意のプログラム、現実の調理などはこの操作対象に含みません。
できない部分は画面上の構成に置き換え、必要に応じて短い説明を返すよう指示しています。

## 返答の検証

正本は `Source/SpresenseMaze/LightBoxStyle.h/.cpp` の形式と検証処理です。
従来の景色JSONも読み込めます。現在の拡張形式は `schema:3` に、従来の基本項目と
`particles`、`world`、`camera`、`objects`、`note` を加えます。
景色の保存には形・環境・カメラも含めます。認証キーは景色に含めず、Androidでは別の保護された領域へ暗号化して保存します。

数、数値範囲、形や動作の名前、IDの重複、多角形の自己交差を検証し、
不正な返答では景色を部分的に書き換えません。HTTP 200の返答が検証を通らなければ、
該当箇所と直前の返答を添えて一度だけ修正を依頼します。通信や認証の失敗では自動再送しません。
処理中に別の景色を選んだり戻したりすると、その返答と修正依頼も取り消します。
1回の通信の制限時間は90秒です。

最大数でのCPU負荷を抑えるため、群れの近傍探索は空間分割・近傍数制限・30Hz更新を使います。
光の描画はインスタンスをまとめ、画面上のグローは256個まで、粒が多い場合は軌跡の描画数も減らします。
粒とセンサー入力のシミュレーションはネットワーク応答を待ちません。

## schema 3 の動作記述

schema 2 の保存済み景色も読み込めます。新しい送信・保存は schema 3 です。

- `parent` は別の物体の `id`。位置と回転は親から継承します。親の `size` は形状に焼き込むため、子の位置の単位は引き続きcmです。
- `pivot` は物体のローカル座標で指定した回転軸。基準姿勢での位置を維持し、回転する親にも付いていきます。
- `motions` は1物体につき最大6チャンネル。`translate`・`rotate`・`scale`・`orbit`・`path`・`flow`・`stream`・`bend`・`ripple` を組み合わせます。`axis`、`amplitude`、秒単位の `period`、周期単位の `phase`、`wave`（sine/triangle/saw）で制御します。
- `path` のチャンネルは物体の位置に足すローカル座標の経路。閉じた経路は位置と接線がつながる補間を使います。`closed:false` では往復します。`orient` で進行方向を向かせます。
- `tube`・`ribbon` は2〜24点の `curve` をローカルcmで指定。`radius` は半径またはリボンの半幅。これらは `size` で拡大せず、曲線を直接立体化します。`closed:true` は閉曲線です。
- `flow` は曲線の始点から終点に向けて材料を吸い上げる表現。麺など、終点で材料が消費される動作に使います。注ぐ液体・滝・管の輸送には、全経路がつながる `stream` を使います。終点を口・吸入口へ接続してください。流体力学や実際の調理を行う機能ではありません。
- `bend` は回転軸から離れるほど大きく曲げる変形。`ripple` は頂点に伝わる波で、水面や布に応用できます。
- `bird` の `fly` は軌道上の移動と羽ばたき、`flutter` はその場の羽ばたき。複合物は `group` を親にして、子の関節回転と軌道移動を組み合わせられます。
- `particles.formation` を `volume` 以外にすると、群泳でも個別の目標位置を保ち、集団で形を作ります。`formationNext` と `formationPeriod` で形を変化させ、`points` の正規化座標で任意の輪郭を作れます。
- `camera.autoFrame:true` は動く物体・粒の範囲を測って構図を決めます。環境用の大きな水面などは `focus:false` にします。

生成する頂点の見積りは全体25万、変形する部分6万まで。循環する親、存在しない親、範囲外の数値、未対応のキーは原子的に拒否します。
「飛ぶ鳥」「すする」「群れの形」の明らかな動作漏れは意味の検証でも検出し、一度だけAIへ修正を要求します。一般的な演出全体の美術・意味を自動採点する機能ではないため、任意の指示の完成度は生成内容に依存します。

`景色の見本` に新しい6場面（潮風の翼／ひとくちの湯気／ひとつになる群れ／木陰のサファリ／ゆっくり、ひらく／時を運ぶ装置）を追加しています。すべて同じ公開された記述形式で作られ、選択・再表示にはAI通信を使いません。

新しい語彙と動作：

- `stream`：tube/ribbon全長を保ち、流れる明るさと半径の変化を付ける。`flow`は従来どおり終点で消費される動作。
- `anchor`／`parentAnchor`：center、x-/x+、y-/y+、z-/z+。非centerのanchorではpositionが関節位置。親の端に付けるときはparentAnchorを使い、同じ位置をpositionへ二重に足さない。
- `startObject`／`endObject`、`startAnchor`／`endAnchor`、`startOffset`／`endOffset`：管・麺などの端点を動く別部品へ接続する。
- motionの`space:local`：基準姿勢の軸で回転・移動・公転。省略時のparent軸は既存景色との互換性のため維持。
- `butterfly`／`whale`／`petal`／`roof`／`gear`／`blossom`：蝶、クジラ、曲面の花弁、山形の屋根、穴と歯のある歯車、茎と葉と花弁が接続済みの花。
- `spinLocal`：歯車などを自分のZ軸で回す。`blossom`の`bloom`は花弁の根元を保って開閉。amplitudeは15〜80度、speedで周期を変える。

群れは形に沿う初期配置、近い粒の対応付け、変形先の速度を使った追従へ変更しました。噴水・火はcenter.Zから発生し、下へ戻った粒も発生点へ戻します。限定編集（背景・照明・カメラ・枠・粒数・速度）では、その項目だけを採用して他の値を元の景色から保持します。全景色を描き直させた結果の無関係な変更をそのまま採用しません。

自動構図は変形中の形も測り、全体表示時の過度な拡大を抑えます。文字や流体物理など未対応の機能については、アプリも制限を補足します。正確な文字描画、透明ガラス、流体物理、動的経路探索、音生成は追加していません。

同じ40件の主観的な画像評価は2.08→3.20/5。問題例を多く含む選定であり、全100件の改善率や統計的保証ではありません。受付件数を美術品質の成功率と見なさず、未達例を残しています。初回100返答の最終版での再検査は97件受付・3件拒否（群れの意味不一致、彫刻の欠落、範囲外の値）。古い保存景色の読み込みはParseを使い、生成時の追加検査とは区別します。
